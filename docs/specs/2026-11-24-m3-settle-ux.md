# M3 Settle up: UX brief (screens)

Date: 2026-11-24. Companion to `docs/specs/2026-11-24-m3-settle-venmo.md` (the "spec"). The spec owns data, contracts and money math. This brief owns layout, states, copy and accessibility for the settle screens. User answers Q1–Q10 are decided. The staff engineer's technical notes (2026-11-24) are folded in. The user asked us not to block on questions, so every open choice here has been decided. Each decision is logged in `docs/decisions-to-review.md` → "Added while building" (M3-UX-1 … M3-UX-15), and the spec's tasks and criteria are amended to match (spec, "Amendment A1").

Built from: `app/(app)/bills/[id]/index.tsx`, `app/(app)/profile.tsx`, `components/VenmoPrompt.tsx`, `components/SharePanel.tsx` (inline confirm), `app/(app)/bills/[id]/edit.tsx` (inline confirm), `components/ui/*`, `lib/useBill.ts`, `.claude/skills/ui-ux-designer/SKILL.md`, and the `[area: expo]` lessons.

## 1. Jobs and rules

| Who | Job | The one next step on screen |
|---|---|---|
| Person who owes | "Pay what I owe in one tap, then be done." | **Pay Hana $15.10 on Venmo**, then **I paid** |
| Payer | "See who has paid me." | None: the status list is the answer. If they have no Venmo: **Add Venmo** |
| Host | "Say who actually paid the restaurant." | A quiet **Change** next to "Hana paid the bill" |
| Nothing owed | "Confirm I'm done." | None |
| Negative share | "Know the payer owes me, outside the app." | None |

Rules:
- One primary button at most, and it moves money or unblocks the person.
- Each action has one home. Activity stays on the bill screen; the payer picker lives only on Settle up.
- No modals and no `Alert`. Confirms are inline, in the `SharePanel` pattern (React Native Web has no `Alert`).
- **Show only what the server has confirmed.** No optimistic marks, undos or payer changes. A button shows its loading state until the refetch that includes the change has landed.
- Components do no money arithmetic. Every amount and every money sentence comes from `lib/settle.ts` and `lib/settleView.ts`, through `formatCents`.
- Status is never colour-only: each status has a glyph **and** a word.

## 2. Screen and files

- Route: `app/(app)/bills/[id]/settle.tsx`, a sibling of `activity.tsx`. It uses `useBill(id)` for live data, refetch on focus and refetch on foreground.
- Components:
  - `components/SettleCard.tsx`: "your part", every role and state in §3.
  - `components/SettlePeopleList.tsx`: the Everyone list with per-row Undo (§4).
  - `components/PayerPicker.tsx`: inline list plus inline confirm (§5).
- Copy and view-model: `lib/settleView.ts`. Every string in §10 is a constant or a pure function there, including the money sentences.

Shell: the same as `profile.tsx`. A scroll view, then a column with `maxWidth: 560` (the bill screen's width, so desktop web is a centred column) and `space.lg` gaps. No sticky footer: the screen is short.

## 3. SettleCard: one card per role and state

A `Card` with no title. Inside, top to bottom:
1. The label (`type.label`).
2. The amount (`MoneyText size="display"`, the largest number on screen).
3. A status line (caption).
4. The buttons: the primary is `block`; the others are ghost.

The label/amount slot stays in the same place in every state, so the card doesn't jump.

### 3.1 Owes, not marked, before Pay (default)
```
┌──────────────────────────────────────┐
│ You owe Hana                         │
│ $15.10                               │
│                                      │
│ [   Pay Hana $15.10 on Venmo     ]   │  primary, block
│ @hana-1 · $15.10                     │  caption, muted. Always visible (see below)
│ On a computer? Send it from the      │  caption, muted. Web only
│ Venmo app on your phone.             │
│                                      │
│ I already paid                       │  ghost
└──────────────────────────────────────┘
```
- **Handle line:** `@hana-1 · $15.10` on every platform (Q8's line). It lets a mistyped handle be caught before money moves. It's also the fallback when a web popup was blocked, which can't be detected. The "On a computer?" line shows on all web visits, because desktop detection isn't reliable.
- **"I already paid"** covers cash and other apps. It marks with no confirm, because Undo is one tap away.
- **The Pay handler calls `openPaymentLink(url)` first, synchronously, with no `await` before it.** Browsers allow a popup only inside the user's gesture. Only after that call does it switch the card to 3.2.

### 3.2 Owes, after tapping Pay
```
┌──────────────────────────────────────┐
│ Did you pay Hana?                    │
│ $15.10                               │
│                                      │
│ [            I paid              ]   │  primary, block
│ @hana-1 · $15.10                     │  still visible (+ the web line on web)
│ Open Venmo again                     │  ghost
└──────────────────────────────────────┘
```
- **The prompt is decided by the tap, not by detecting a return** (M3-UX-1). There's no `AppState` or visibility listening:
  - iOS goes `inactive` for Control Center and Face ID.
  - A blocked popup on web can't be detected.
  - Mobile Safari may reload the tab, and the OS may kill the app.
  Switching on the tap is deterministic and never prompts falsely. When the person comes back, the question is already on screen.
- The state is component state, `openedVenmo: { payerId, cents } | null`. Nothing is persisted and there's no module state. If the app or tab reloaded, they land on 3.1, where "I already paid" still gets them there in one tap.
- If a refetch shows a different payer or amount than `openedVenmo` holds, the state is dropped. The card shows the current role's default, under the §6 payer-changed banner. There is **no** button that marks a payment to the old payer.
- "I paid" calls `markPaid(bill, openedVenmo.payerId, openedVenmo.cents)`. While it runs, the button shows loading and is disabled. "Marked paid" shows only after the refetch has the mark.

### 3.3 Owes, marked
```
┌──────────────────────────────────────┐
│ You paid Hana                        │
│ $15.10                               │  mark.cents
│ ✓ Marked paid                        │  success colour + glyph + word
│                                      │
│ Undo                                 │  ghost, no confirm (own mark)
└──────────────────────────────────────┘
```

### 3.4 Owes, marked, share changed since (Q3 A)
The label and amount stay "You paid Hana / $15.10". The status line becomes a warning (`⚠`, warning colour). The text comes from `lib/settleView.ts`, using `markDiffCents` from `lib/settle.ts`:

| Current share vs mark | Status line |
|---|---|
| higher (1620 vs 1510) | `⚠ Your share is now $16.20. Sort out the $1.10 with Hana.` |
| lower, above 0 (1400 vs 1510) | `⚠ Your share is now $14.00. Hana owes you $1.10 back.` |
| $0.00 (role now `nothing`) | `⚠ Your share is now $0.00. Hana owes you $15.10 back.` |
| negative (role now `payer_owes_them`, −100 vs 1510) | `⚠ Your share is now -$1.00. Hana owes you $16.10 back.` (`formatCents` writes an ASCII `-`) |

- Undo stays. There's no "pay the difference" button in v1 (M3-UX-7).
- The marked card wins over the role: a marked person whose role became `nothing` or negative still sees this card.

### 3.5 Owes, and the payer has no Venmo
```
┌──────────────────────────────────────┐
│ You owe Hana                         │
│ $15.10                               │
│ Hana hasn't added Venmo yet. Ask     │  caption muted
│ them, or pay another way.            │
│ [            I paid              ]   │  primary, block (only action)
└──────────────────────────────────────┘
```
When Hana adds a username, this screen sees it on focus or foreground. Profile saves don't broadcast on the bill channel, and no copy promises that it's live.

### 3.6 Nothing owed
"You're all set" / "You don't owe anything on this bill." No amount, no buttons.

### 3.7 Negative share (Q6)
"Hana owes you" / "$1.00" / "Settle that outside the app." No buttons.

### 3.8 You are the payer
```
┌──────────────────────────────────────┐
│ 3 people owe you                     │  "1 person owes you"
│ $45.20                               │  collectCents
│ 1 of 3 paid                          │  polite live region
└──────────────────────────────────────┘
```
- **All paid:** "Everyone's paid" / `$45.20` / `✓ All 3 marked paid`.
- **Nobody owes you:** "Nobody owes you anything on this bill." No amount.
- **No Venmo username:** a card **above** this one, with the screen's primary button. It can't be dismissed here: without a username nobody can pay you in one tap.
  ```
  Add your Venmo so people can pay you
  [          Add Venmo             ]   → /profile (refetch on focus)
  ```

### 3.9 Blocked: unclaimed items
```
┌──────────────────────────────────────┐
│ Not ready yet                        │
│ You can settle up once every item is │
│ claimed (3 items left).              │
│ Your "I paid" is saved.              │  caption; only if the viewer is marked. No amount
│ [        Back to the bill        ]   │  primary → dismissTo
└──────────────────────────────────────┘
```
A blocked plan shows **no amounts** and no Everyone list. The payer line and "Change" stay.

### 3.10 Blocked: every item is $0 (`blocked_all_zero`, Q10)
- **Host:** `SETTLE_ALL_ZERO_COPY` = "Every item is $0. Fix the prices, or switch to Split evenly." Primary "Edit items" (→ `/bills/<id>/edit`), then a ghost "Back to the bill".
- **Everyone else:** `SETTLE_ALL_ZERO_GUEST_COPY` = "Every item is $0. Ask Hana to fix the prices." Primary "Back to the bill" (M3-UX-9).

### 3.11 Blocked: bad payer (`blocked_bad_payer`)
"Something went wrong loading this bill." with the primary "Try again", which calls `refetch()`. **No automatic refetch.**

### 3.12 Errors from actions
Each error shows as `Banner tone="error" alert` under the card's buttons. The button re-enables.

| Cause | Copy | Then |
|---|---|---|
| `network` | "Couldn't save. Try again." | none |
| `payer_changed` | existing `BILL_ERROR_COPY.payer_changed` ("Who gets paid just changed. Check the amount and try again.") | refetch |
| `not_complete` | existing `BILL_ERROR_COPY.not_complete` ("Some items aren't claimed anymore. You can settle up once every item is claimed.") | refetch |
| `not_allowed` | existing `BILL_ERROR_COPY.not_allowed` | none |
| `invalid_bill` | "Couldn't save. Refresh and try again." This is settle-specific copy in `settleView`: the existing `BILL_ERROR_COPY.invalid_bill` talks about editing | refetch |
| `openPaymentLink` → `{ ok: false }` (native only) | "Couldn't open Venmo. Send $15.10 to @hana-1 in the Venmo app." | still go to 3.2 |

`BILL_ERROR_COPY.marks_changed` (existing: "Someone marked that they paid just now. Check who'll be affected and try again.") is seen only in the picker (§5). The existing strings are kept as written (M3-8), so `lib/bills.ts` needs no copy change.

## 4. SettlePeopleList: everyone (Q5)

```
┌ Everyone                    1 of 3 paid ┐
│ You            $15.10       ✓ Paid      │
│                                  Undo   │  ghost, only for Q4's callers
│ Dee            $20.00         Not yet   │
│ Sam            $10.10       ✓ Paid      │
│   Marked $9.00 · share now $10.10 ⚠     │  warning sub-line
│ Ana            -$1.00                   │
│   Hana owes Ana. Settle outside the app.│  muted sub-line
└─────────────────────────────────────────┘
```
- **Rows:** role `owes` plus `payer_owes_them`. Not the payer (already on the payer line), and not `nothing`, except a `nothing` person who has a mark, shown with the share-changed sub-line. The viewer comes first as "You", then `displayShares` order. **The order is stable**: rows don't move when someone pays.
- **Status:** `✓ Paid` (success colour) or `Not yet` (muted word).
- **Undo:**
  - Your own row acts at once.
  - **Someone else's** row swaps the row's Undo for an inline "Undo Sam's "I paid"?" with a danger "Undo" and a ghost "Cancel" (M3-UX-3).
- **Payer's view of a negative row:** "You owe Ana $1.00. Settle that outside the app."
- **Aside:** `paidCount of (paidCount + owingCount) paid`; `✓ All paid` when `allPaid`. When nobody owes, the card isn't shown.

## 5. PayerPicker (host)

```
Hana paid the bill                 Cancel      ← "Change" becomes "Cancel"
┌ Who paid the bill? ───────────────────────┐
│ ◉ You                                     │  radio rows ≥ 44 pt
│ ○ Sam                                     │
│ ○ Dee                                     │
└───────────────────────────────────────────┘
```
Tapping someone other than the current payer:
1. The row shows a spinner, and the screen **re-reads the bill**.
2. **Confirm rule (M3-UX-4).** With the fresh data:
   - **Marks > 0:** "Switch to Sam? This clears 2 "I paid" marks (Dee, You)."
   - **0 marks, bill complete:** "Switch to Sam? People may already be paying Hana." People can see Pay buttons only once the bill is complete, so someone may be in Venmo right now.
   - **0 marks, bill not complete:** no confirm. Nobody can have started paying.

   The confirm shows a danger "Switch to Sam" and a ghost "Cancel".
3. `setPayer(bill, X, <marks counted in step 1>)`. On success, after the refetch: the picker closes and the payer line updates. On `marks_changed`: refetch, and the confirm re-renders with the new count and names, with the existing `BILL_ERROR_COPY.marks_changed` above it.
4. Cancel makes no call. Tapping the current payer closes the picker with no call.

"Change" shows only for the host, and only when there are at least 2 participants.

## 6. Notices (the banner slot under the payer line)

The screen keeps `shownPayerId` and `myMarkShown` from the last data on screen, like `edited` in `useBill`, and compares them on each refetch.

| When | Banner | Tone / dismiss |
|---|---|---|
| `payer_id` changed, and this viewer didn't just call `setPayer` | "Sam is now collecting for this bill." When the viewer's mark was cleared, or `openedVenmo` pointed at the old payer, add: " If you already paid Hana, sort it out with them." | warning, `alert`; ghost "Dismiss" |
| The viewer's mark disappeared, the payer is unchanged, and the viewer didn't tap Undo | "Your "I paid" was undone. Check Activity to see who." | warning, `alert`; "Dismiss" |
| Live paused | the existing caption row | "Refresh" |

The copy names no actor, because `BillData` doesn't say who did it. Activity does.

## 7. Entry point on the bill screen (Task 10, M3-UX-8)

One button in the **sticky footer**, under `SharesSummary`. It's the bill screen's only primary button.

| Bill state | Footer |
|---|---|
| 1 participant | nothing new (the job is sharing the link) |
| ≥ 2 participants, not complete | secondary "Settle up", with the caption "3 items left to claim" beside it. It still opens Settle up |
| ≥ 2 participants, complete | **primary** "Settle up" |

- `accessibilityLabel="Settle up"`. Hint: "3 items left to claim first" / "See what you owe and pay".
- `N` is `displayShares(...).unclaimedRows`, which the screen already computes.
- Why the footer rather than the top bar: the moment the last item is claimed, the next step should appear where the person's thumb and eyes already are, next to their share. A ghost button in the top bar is easy to miss, and it would make Activity and Settle look equally important.

## 8. Accessibility

- **Touch targets:** every control is the `Button` primitive (44 pt minimum) or a `Pressable` row of at least 44 pt. Ghost buttons with zeroed padding (`edgeButton`) get `hitSlop`.
- **Labels** (a custom row label must include everything the row shows):
  - Pay: "Pay Hana $15.10 on Venmo, to @hana-1", hint "Opens Venmo". "Open Venmo again": hint "Opens Venmo".
  - "I already paid" / "I paid": hint "Marks your share as paid".
  - Everyone rows:
    - "Sam, $10.10, paid";
    - "Dee, $20.00, not paid yet";
    - "Sam, marked paid $9.00, share is now $10.10";
    - "Ana, Hana owes Ana $1.00, settle outside the app".
  - Undo: "Undo Sam's I paid" / "Undo your I paid".
  - Picker: rows have `accessibilityRole="radio"` and `accessibilityState={{ checked }}`. The group label is "Who paid the bill?". "Change": hint "Choose who paid the restaurant".
- **Announcements:**
  - Errors and the §6 notices use `Banner alert`.
  - "Marked paid" / "Marked not paid" follow the `profile.tsx` pattern: `announceForAccessibility` on iOS, and a polite live region on Android and web.
  - The payer's "1 of 3 paid" is a polite live region.
  - There's no return-from-Venmo announcement (no detection).
  - After Pay swaps the card, check where VoiceOver focus lands. It's acceptable if focus goes to the card's label.
- **Never colour alone:** ✓ + "Paid"; the word "Not yet"; ⚠ + words; the radio glyph + `checked`. Glyphs are `accessible={false}`.
- **Focus order:** back, title, payer line, Change, banner, card (label, amount, status, primary, secondary), Everyone. On web, everything is reachable by Tab with a visible focus ring.
- **Dynamic Type and motion:** no fixed heights; long labels wrap; at large sizes a row's status wraps under the name. No animations.
- **Contrast:** existing token pairs only. Compute the ratio for any new pair.
